# FHIRPath 3.0.0 conformance audit and implementation plan

Audited November 21, 2026 on PR #77 at `97b0414cfc2820bea6e211cbcc4fb702969aad37`. The target is HL7's published FHIRPath 3.0.0 STU 3, including the language sections marked Standard for Trial Use. The published grammar governs syntax. The FHIR R4 and R5 specifications govern their respective logical models and host functions. [PR #77](https://github.com/reason-healthcare/rh/pull/77) · [FHIRPath 3.0.0](https://hl7.org/fhirpath/STU3/en/index.html) · [Grammar](https://hl7.org/fhirpath/STU3/en/grammar.html) · [Release changes](https://hl7.org/fhirpath/STU3/en/changes.html) · [FHIR R4](https://hl7.org/fhir/R4/fhirpath.html) · [FHIR R5](https://hl7.org/fhir/R5/fhirpath.html)

RH needs changes to the core grammar and evaluator before it can claim 3.0.0 conformance. The largest gaps are scope and singleton evaluation, typed comparison and arithmetic, missing STU functions, and logical FHIR node handling. The FHIRPath crate, CLI, WASM bindings, and validator share parts of this behavior, so the plan includes tests at each public entry point.

## Base language gaps

The examples below were reproduced on the PR-head CLI. In these tables, `{}` denotes an empty FHIRPath collection, which the CLI renders as JSON `null`.

| Area | Reproduced behavior and published result | Evidence |
| --- | --- | --- |
| Operator precedence and lexing | `1 * 2 is Integer` parses as a multiplication of `1` and a Boolean. It should test the product's type and return `true`. `true in 1 = 1` returns `false` because membership binds at equality precedence. It should return `true`. An empty collection with whitespace or a comment between the braces fails to parse. | [Parser](../../crates/rh-fhirpath/src/parser.rs#L227) · [Grammar](https://hl7.org/fhirpath/STU3/en/grammar.html) · [Precedence](https://hl7.org/fhirpath/STU3/en/index.html#operator-precedence) |
| Focus and variables | Top-level `$index` returns `{}` instead of `0`. `(1 \| 2).select(1.select($index))` yields `[0,1]` instead of `[0,0]`. Within `name.select(%context.id)`, a Patient's initial context is lost. An undefined external such as `%undefined` yields `{}` instead of an error. | [Context](../../crates/rh-fhirpath/src/evaluator/core/context.rs#L46) · [Variable evaluation](../../crates/rh-fhirpath/src/evaluator/core/evaluator.rs#L175) · [Special variables](https://hl7.org/fhirpath/STU3/en/index.html#special-variables) · [Environment variables](https://hl7.org/fhirpath/STU3/en/index.html#environment-variables) |
| Singleton and empty semantics | `1.where(true \| false)` returns `1`. The same multi-item predicate succeeds in `exists` and `all`. Each should signal a cardinality error. A type test against an unknown type such as `1 is System.MissingType` returns `false` where type resolution calls for an error. | [Scoped evaluation](../../crates/rh-fhirpath/src/evaluator/core/evaluator.rs#L520) · [Type operations](../../crates/rh-fhirpath/src/evaluator/types/operations.rs#L187) · [Singleton rules](https://hl7.org/fhirpath/STU3/en/index.html#singleton-evaluation-of-collections) · [Type operators](https://hl7.org/fhirpath/STU3/en/index.html#types) |
| Equality and collection operations | `'a'.split(',') in 'a'` returns `false` for a singleton left operand. | Integer and Decimal | `'2147483648'.toInteger()` exceeds the signed 32-bit range. `(-2147483648) div -1` also returns an out-of-range Integer instead of `{}`. `5.5 div 0.7` yields an Integer where the result is Decimal. The parser also substitutes zero when some numeric literals exceed the representation. | [Literal parsing](../../crates/rh-fhirpath/src/parser.rs#L619) · [Division](../../crates/rh-fhirpath/src/evaluator/operations/arithmetic.rs#L769) · [Conversion](../../crates/rh-fhirpath/src/evaluator/functions/conversion_functions.rs#L272) · [Integer conversion](https://hl7.org/fhirpath/STU3/en/index.html#tointeger--integer) · [Math operators](https://hl7.org/fhirpath/STU3/en/index.html#math-1) |
| Temporal comparison, conversion, and arithmetic | Two equal instants on different local calendar dates compare unequal, for example `@2024-01-01T23:00:00Z = @2024-01-02T01:00:00+02:00`. Date-to-DateTime conversion introduces midnight where it should preserve date-only precision. `@2026-02 + 4 weeks` advances to March in RH while the spec gives February. Adding minutes to a DateTime with minute precision errors. | [Temporal comparison](../../crates/rh-fhirpath/src/evaluator/operations/temporal.rs#L169) · [Arithmetic](../../crates/rh-fhirpath/src/evaluator/operations/arithmetic.rs#L901) · [Temporal conversion](../../crates/rh-fhirpath/src/evaluator/functions/conversion_functions.rs#L576) · [DateTime equality](https://hl7.org/fhirpath/STU3/en/index.html#datetime-equality) · [Date/time arithmetic](https://hl7.org/fhirpath/STU3/en/index.html#datetime-arithmetic) |
| Quantity and UCUM | RH treats `1 'ug' = 1.00000001 'ug'` as equal because of floating-point tolerance on converted values. Division by zero raises an error instead of yielding `{}`. Scalar divided by a quantity with units is rejected, so `60 / 1 's'` cannot produce the reciprocal unit. Calendar durations and UCUM time units also differ in equality, equivalence, and arithmetic and need operation-specific tests. | [Quantity arithmetic and equality](../../crates/rh-fhirpath/src/evaluator/operations/units.rs#L684) · [Quantity equality](https://hl7.org/fhirpath/STU3/en/index.html#quantity-equality) · [Math operators](https://hl7.org/fhirpath/STU3/en/index.html#math-1) |

## FHIR model and host gaps

- **Logical FHIR nodes.** The active metadata lookup is R4-specific and depends on JSON `resourceType` to type members. It loses datatype provenance on nested nodes. A Patient with only `_birthDate.extension` returns `false` from `birthDate.extension(url).exists()`. Support metadata-only and repeated primitives, choice elements, logical children, and subtype relationships for `is`, `as`, and `ofType`. Verify R5 `integer64` as `System.Long` and Coding/CodeableConcept equivalence. Treat focus, the starting context node, the containing resource, and the root resource as distinct values. [Metadata](../../crates/rh-fhirpath/src/evaluator/metadata.rs#L9) · [Navigation](../../crates/rh-fhirpath/src/evaluator/core/evaluator.rs#L313) · [FHIR R5 logical types](https://hl7.org/fhir/R5/fhirpath.html#types) · [FHIR JSON primitives](https://hl7.org/fhir/R5/json.html#primitive)
- **FHIR functions.** `conformsTo` currently compares the profile URL suffix with `resourceType`. A Patient with an invalid administrative gender returned `true` for the base Patient profile probe. `resolve`, `memberOf`, `subsumes`, `subsumedBy`, `htmlChecks`, and the applicable element definition, slice, and modifier functions need real capabilities. The validator has a terminology service, while its invariant evaluation creates an unconfigured FHIRPath context. Record R4/R5 differences for unresolved profiles and value sets, cardinality, and empty results. Build on the existing FHIR interoperability proposal and track draft host APIs such as `%terminologies`, `%factory`, and `%server` when a host claims those capabilities. [Conformance stub](../../crates/rh-fhirpath/src/evaluator/functions/collection_functions.rs#L69) · [Validator invariant evaluation](../../crates/rh-validator/src/validator.rs#L6103) · [OpenSpec proposal](../changes/fhirpath-fhir-interop-functions/proposal.md) · [FHIR R4 functions](https://hl7.org/fhir/R4/fhirpath.html#functions) · [FHIR R5 functions](https://hl7.org/fhir/R5/fhirpath.html#functions)

## Implementation sequence

1. **Establish a versioned conformance baseline.** Pin XML test revisions and matching inputs. Extend the native harness to consume the relevant R5 cases and honor model version, starting element and type, order, and mode. Keep CLI evaluation as an end-to-end check. Validate genuine errors and typed values at the Rust boundary. Resolve XML-only fixture coverage with verified JSON equivalents or a fixture importer, and document suite cases whose profile, model, or feature falls outside the release target. Track exceptions by case ID and reason. Gate on no new failures, unexpected errors, or unexplained skips.
2. **Fix correctness in the shared evaluator.** Align the nom precedence and token rules with the published grammar. Centralize singleton extraction and the three-valued equality result used by operators, collections, and scopes. Fix the context and index lifetimes and add typed regression expressions for empty, singleton, and multi-item inputs. Implement checked Integer, Long, and Decimal arithmetic, preserve temporal precision and timezone semantics, and make malformed input return through the normal error or empty-result path. Validate existing downstream invariants and CPG evaluation for expressions whose results change.
3. **Complete the STU language.** Build lazy `coalesce`, lexical variable binding for `defineVariable`, duplicate-preserving `repeatAll`, and fallible multi-key sort on the evaluator fixes. Complete Long promotion and conversion, aggregate operations, temporal interval functions, date-format codes, boundaries, component extraction, and string codec behavior. Use shared temporal and Quantity operations across operators and functions. Test the signed numeric bounds, mixed supported types, precision mismatch, timezone offsets, tie-breaking, laziness, variable scope, and Unicode round trips.
4. **Complete model-aware evaluation.** Supply the FHIR release's metadata with the evaluation context and preserve node identity and FHIR types through selection, indexing, and projection. Implement the constructor grammar and typed construction, per-item reflection, and `pathname` against that metadata. Use paired R4/R5 resource tests for repeating primitives with extensions, choices, subtype casts, and source paths. Wire host-provided resolver, validator, and terminology services through the existing FHIR extension surface. Test local, contained, Bundle, and unresolved references and same-resource-type instances that differ in profile conformance.
5. **Qualify the public surfaces and update the claim.** Run the pinned suites and 3.0.0 semantic probes in the Rust library, check representative results and diagnostics through `rh fhirpath` and the WASM package, and exercise FHIR-backed invariants through `rh-validator`. Require all applicable tests for the advertised language and each advertised FHIR release/service capability to pass, with documented upstream expectation conflicts backed by published-spec tests. Refresh the two coverage documents with the release, fixture revisions, counts, and supported model and service capabilities. HL7 permits runtime checking, so a separate static type checker is optional. [Runtime and compile-time checking](https://hl7.org/fhirpath/STU3/en/index.html#type-safety-and-strict-evaluation)

## Reproduce the baseline

Run from the repository root on the audit base. The two R5 runs produce per-case JSON.

```bash
cargo build --locked -p rh-cli --bin rh
cargo test --locked -p rh-fhirpath --test hl7_conformance -- --nocapture

audit_dir=$(mktemp -d)
fixture_rev=469d90ab58663266d5d7ff82ba3587257fd8a4be
fixture_base="https://raw.githubusercontent.com/FHIR/fhir-test-cases/$fixture_rev/r5"
mkdir "$audit_dir/inputs"
curl -fsSL "$fixture_base/fhirpath/tests-fhir-r5.xml" -o "$audit_dir/tests.xml"
for name in appointment-examplereq bundle-document-ips diagnosticreport-eric \
    explanationofbenefit-example patient-container-example patient-name-extensions
do
    curl -fsSL "$fixture_base/$name.json" -o "$audit_dir/inputs/$name.json"
done
for name in codesystem-example conceptmap-example observation-example parameters-example-types \
    patient-example-name patient-example-period patient-example questionnaire-example valueset-example-expansion
do
    curl -fsSL "$fixture_base/examples/$name.json" -o "$audit_dir/inputs/$name.json"
done

python3 crates/rh-fhirpath/testlab/run_r5_testlab.py --rh "$PWD/target/debug/rh" \
    --suite "$audit_dir/tests.xml" --input-dir "$audit_dir/inputs" \
    --no-baseline-check --report-format json --report "$audit_dir/upstream-r5.json"
python3 crates/rh-fhirpath/testlab/run_r5_testlab.py --rh "$PWD/target/debug/rh" \
    --no-baseline-check --report-format json --report "$audit_dir/vendored-r5.json"
```
